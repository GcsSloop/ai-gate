# Skill 仓库扩展与排序/限流/缓存体积控制计划（2026-04-10）

## 背景

发现技能仓库列表需要同步引入 [cc-ai 排行榜](https://cc-ai.cn/skills-cn/frontend/index.html) 中的全部 GitHub 仓库，并按 star 数排序。同时，仓库数量显著增加后，需要降低一次刷新触发 API 限额风险，并限制本地缓存体积。

## 目标

1. 默认仓库覆盖排行榜中的全部 GitHub 仓库。
2. 默认仓库按 star 数降序排列。
3. 刷新发现技能时降低突发请求，降低限额触发概率。
4. 发现技能缓存文件增加体积上限，避免无限增长。

## 方案

1. 新增默认仓库种子列表（含 owner/name/branch/star），由后端启动时自动按 star 排序生成默认仓库。
2. 发现技能按仓库扫描时，对 GitHub 仓库请求引入固定节流间隔。
3. GitHub archive 拉取增加限流场景重试（指数退避简化版）。
4. 缓存写入前进行压缩：
   - 截断超长描述。
   - 空安装状态不落盘。
   - 超过体积阈值时按比例裁剪条目，确保缓存大小受控。

## 验证

1. `go test ./internal/api -count=1`
2. 重点验证：
   - 默认仓库顺序符合 star 排序；
   - 发现技能刷新在默认仓库扩展后仍可通过；
   - 旧缓存兼容，刷新后缓存体积受控。

## 风险与回滚

- 风险：排行榜仓库规模扩大后，首次刷新耗时增加。
- 缓解：节流 + 限流重试 + 缓存裁剪。
- 回滚：回滚本次提交即可恢复旧默认仓库与旧缓存策略。
